# 横断デザイン原則

全プロダクト共通の単一の情報源。`ux-designer` はここに書かれたことだけを根拠に判断する。
**ここに書いていない色・余白・パターンを発明することを禁止する。**

プロダクト固有の値（実際のカラーコード等）は各リポジトリの
`.claude/design/design-tokens.md` に置く。この文書は「守るべき制約」だけを書く。

---

## 1. 状態を先に決める

無人運用で UI が破綻する最大の原因は、**正常系だけが実装されること**である。
実装者は仕様に書かれていない状態を作らない。

すべての画面仕様は次の8状態について「表示内容」または「該当なし」を明記する。
1つでも空欄があれば仕様として不完全であり、実装に渡さない。

| 状態 | 決めること |
|---|---|
| 初期 / 読込中 | スケルトンかスピナーか。レイアウトシフトを起こさないか |
| 空 | 何を表示し、**次に何をすべきか**を示すか |
| 正常 | 画面構成 |
| 送信中 | 操作をどう封じるか（二重送信の防止） |
| 成功 | どう伝えるか。何秒出すか |
| 失敗 | **原因と次のアクション**を示す文言 |
| 権限なし | 隠すのか、無効化して理由を示すのか |
| オフライン / 通信断 | 該当なしでもよいが、明記する |

## 2. 文言は仕様に含める

実装者に文言を考えさせない。考えさせると「エラーが発生しました」が量産される。

- エラー文言は**何が起きたか + 次に何をすべきか**の2要素を含む
- 禁止: 「エラーが発生しました」「失敗しました」「問題が発生しました」（単体で）
- 良い例: 「保存できませんでした。時間をおいて再度お試しください」
- 良い例: 「メールアドレスの形式が正しくありません」
- 専門用語・内部用語（テーブル名、HTTPステータス、例外クラス名）を画面に出さない

## 3. 既存パターンの再利用を新規作成より優先する

プロダクトが増えるほど、一貫性の欠如が最も高くつく負債になる。
`ux-designer` は新規コンポーネントを提案する前に、既存の類似画面を必ず読む。
新規に作る場合は**なぜ既存で足りないのか**を仕様に書く。

## 4. トークン以外の値を使わない

色・余白・フォントサイズ・角丸・影は、すべて `design-tokens.md` の
CSS 変数を経由する。**ハードコードされた `#3b82f6` や `margin: 13px` は
`code-reviewer` が MAJOR として差し戻す。**

トークンに必要な値がない場合、勝手に近い値で代用しない。
「トークンの追加提案」として書き、`needs-human` を付けて人間の判断を待つ。
デザインシステムの拡張は、無人で決めてよい範囲を超えている。

## 5. アクセシビリティは数値で守る

主観が入る余地をなくすため、機械的に測れる基準だけを必須とする。
`design-qa` がこれを Preview 環境で実測し、外れたら**マージを止める**。

| 項目 | 閾値 | 根拠 |
|---|---|---|
| 本文テキストのコントラスト比 | 4.5:1 以上 | WCAG 2.1 AA |
| 大きい文字(18.66px以上 or 14px以上太字) | 3:1 以上 | WCAG 2.1 AA |
| タップターゲット | 44×44px 以上 | WCAG 2.5.5 / iOS HIG |
| 横スクロールの発生 | 375px 幅で発生しないこと | — |
| axe-core critical / serious 違反 | 0件 | — |
| フォーカス可視 | `outline: none` の単独使用を禁止 | WCAG 2.4.7 |

すべての操作要素は**キーボードだけで到達・実行できる**こと。
画像には `alt`、アイコンのみのボタンには `aria-label` を付ける。

## 6. レスポンシブは3幅で定義する

| 幅 | 想定 |
|---|---|
| 375px | スマートフォン（最小サポート幅） |
| 768px | タブレット |
| 1440px | デスクトップ |

仕様にはこの3幅それぞれの挙動を書く。中間幅は連続的に変化するものとして扱う。

## 7. 動きは控えめに

- トランジションは 150〜250ms、`ease-out` を基本とする
- `prefers-reduced-motion: reduce` を尊重し、アニメーションを無効化できるようにする
- レイアウトシフト（CLS）を起こす遅延読み込みを避ける

## 8. 判断を人間に上げる条件

`ux-designer` は次の場合に `needs-human` を付けて停止する。

- デザイントークンの追加・変更が必要
- 新しいコンポーネントパターンの追加が必要
- ブランドの印象を変える変更（配色の方向転換、ロゴ、トーン&マナー）
- 状態の表に埋められない欄がある
- 既存の原則と要望が矛盾している

**「デザインの方向性そのもの」は無人で決めてよい範囲を超えている。**
このファイルが薄いほど `needs-human` が増える。運用しながら書き足していくこと。
